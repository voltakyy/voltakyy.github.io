SOAL 01 Bobot: 15 Poin Modul Pertemuan 3 (Hal. 9–12) & Pertemuan 4 (Hal. 2, 3, 7, 8)

"1. Apa yang dimaksud dengan Class dalam konsep OOP dan bagaimana hubungannya dengan Object?"

Kunci Jawaban Resmi Berdasarkan Diktat Pertemuan 3 & 4 UMS

A. Pengertian Class (Blueprint / Template)

Berdasarkan Modul Pertemuan 3 Sub-bab 10 & 11 serta Pertemuan 4 Sub-bab 2.1:
Class adalah blueprint atau template yang mendefinisikan struktur data (property) dan perilaku/aksi (method) yang dimiliki oleh object.

Daripada mendefinisikan property dan method yang sama berulang kali untuk setiap entitas, kita cukup mendefinisikan strukturnya satu kali saja di dalam sebuah Class.

Contoh pada Modul: Class: Robot memiliki struktur:

  • Property (data): warna, posisi, arah, kecepatan
  • Method (perilaku): move(), turnRight(), stop(), say("...")

B. Pengertian Object (Instance)

Berdasarkan Modul Pertemuan 3 Sub-bab 11.2 & Pertemuan 4 Sub-bab 2.2:
Object adalah hasil nyata (instance konkret) yang dibuat berdasarkan class. Object adalah pihak di dalam program yang menjalankan instruksi.

C. Hubungan Class dan Object (One Class ➔ Many Objects)

Banyak object dapat dibuat menggunakan satu class yang sama. Setiap object memiliki struktur property dan method yang sama, tetapi dapat memiliki nilai property yang berbeda.

Object (Instance) Nilai Property (State Berbeda) Method (Struktur Sama)
Robot A warna: biru, posisi: (2, 1), arah: kanan, kecepatan: 2 move(), turnRight(), stop(), say()
Robot B warna: merah, posisi: (4, 2), arah: kiri, kecepatan: 3 move(), turnRight(), stop(), say()
Robot C warna: hijau, posisi: (1, 5), arah: atas, kecepatan: 1 move(), turnRight(), stop(), say()

D. Analogi Resmi Modul: Blueprint Rumah (Halaman 12)

Dari satu blueprint rumah (Class: Rumah dengan property warna, lantai, penghuni, lokasi; method: bangun(), ubahWarna()), kita bisa membuat banyak rumah nyata:

  • Rumah A: warna putih, 2 lantai, penghuni Keluarga A, lokasi Solo.
  • Rumah B: warna cokelat, 2 lantai, penghuni Keluarga B, lokasi Yogyakarta.
  • Rumah C: warna abu-abu, 3 lantai, penghuni Keluarga C, lokasi Bandung.

Pertanyaan Analisis Dosen: "Jika blueprint rumahnya kita ubah, apakah rumah yang dibuat berikutnya memiliki struktur berbeda?"
Jawaban: Ya. Karena blueprint/class mendefinisikan struktur property dan method. Object adalah instance yang patuh pada cetak birunya.

E. Korelasi Langsung pada Alice 3

  • Class berada di Gallery (contoh: Class Bunny atau Robot).
  • Object berada di Scene (contoh: object bunny di posisi (0,0) putih, dan bunny2 di posisi (2,0) biru).
SOAL 02 Bobot: 15 Poin Modul Pertemuan 3 (Hal. 8–9) & Pertemuan 4 (Hal. 4, 9–12)

"2. Apa yang dimaksud dengan State (Property) dan Behavior (Method) pada sebuah object? Jelaskan!"

Kunci Jawaban Resmi Berdasarkan Diktat Pertemuan 3 & 4 UMS

A. Property / State (Apa yang Dimiliki Object)

Berdasarkan Modul Pertemuan 3 Sub-bab 8.1 & Pertemuan 4 Sub-bab 3.1:
Property adalah data atau keadaan (state) yang dimiliki oleh sebuah object.

  • Property menunjukkan apa yang dimiliki oleh object (*what it has*).
  • Property dapat berubah nilainya selama program berjalan (misalnya perubahan posisi robot setelah bergerak).
  • Di Alice 3, nilai property dapat dilihat dan diubah pada panel Properties.
  • Contoh Property pada Modul:
    • warna (color/paint) ➔ biru, merah, hijau.
    • posisi (position) ➔ koordinat (2, 1), (0, 0, 0).
    • arah (orientation/direction) ➔ kanan, kiri, atas, 0° s/d 360°.
    • kecepatan (speed) ➔ 1, 2, 3.
    • ukuran (size/opacity) ➔ scale desimal.

B. Method / Behavior (Apa yang Dapat Dilakukan Object)

Berdasarkan Modul Pertemuan 3 Sub-bab 8.2 & Pertemuan 4 Sub-bab 3.2:
Method adalah aksi atau perilaku (behavior) yang dapat dilakukan oleh sebuah object (*what it does*).

  • Method menentukan apa yang dapat dilakukan oleh object dan dijalankan untuk menghasilkan aksi nyata di layar.
  • Di Alice 3, method disusun di Code Editor.
  • Method dapat membutuhkan informasi tambahan yang disebut parameter / argument (misalnya direction, steps, duration, atau revolutions di mana 0.25 rev ≈ 90°).
  • Contoh Method pada Modul:
    • move() ➔ Menggerakkan robot maju sejumlah langkah (misal robot.move() atau bunny.move(FORWARD, 2)).
    • turnRight() / turn() ➔ Memutar object ke arah tertentu.
    • stop() ➔ Menghentikan pergerakan object.
    • say("...") ➔ Menampilkan balon dialog atau berbicara.
    • jump() ➔ Menggerakkan object melompat ke atas lalu kembali ke bawah.

C. Kesimpulan Resmi Dosen

"Setiap object memiliki property dan method. Property menyimpan data/keadaan object, sedangkan method menentukan apa yang dapat dilakukan oleh object tersebut."

Alur Pembentukan: Class ➔ mencetak ➔ Object ➔ memiliki ➔ Property (Data) + Method (Aksi) ➔ menghasilkan ➔ Behavior (Perilaku Nyata).

SOAL 03 Bobot: 15 Poin Modul Pertemuan 3 (Hal. 4–5: Tabel Objek & Behavior)

"3. Berikan contoh behavior manusia dalam konsep pemrograman berorientasi objek!"

Kunci Jawaban Resmi Berdasarkan Diktat Pertemuan 3 UMS

A. Tabel Resmi Contoh Objek dan Behavior-nya (Modul Pertemuan 3 Hal. 4–5)

Dosen menegaskan bahwa setiap objek memiliki method/behavior yang sesuai dengan karakter objeknya:

Objek Behavior / Method Sesuai Karakter Objek
Character (Manusia) walk(), jump(), say()
Robot move(), turn(), stop()
Car move(), turn(), stop()
Door open(), close(), lock()
Ball move(), roll(), stop()
Animal walk(), jump(), makeSound()

B. Analisis Penting Dosen: "Apakah Semua Objek Dapat Melakukan Behavior yang Sama?"

Jawabannya: TIDAK. Method harus sesuai dengan jenis objeknya!

  • Kasus Modul: Apa yang terjadi jika kita memberikan instruksi open() kepada robot atau move() kepada pintu?
    • open() adalah behavior yang cocok untuk Door, bukan untuk Robot atau Manusia.
    • move() adalah behavior yang cocok untuk Robot, Car, atau Ball, tetapi tidak cocok untuk Door.

C. Pemodelan Behavior Manusia (Character) dalam OOP

Jika Manusia dimodelkan sebagai Class: Character / Manusia, maka behavior yang valid dan realistis adalah:

  1. walk(Direction arah, double langkah): Behavior manusia untuk berjalan berpindah tempat, mengubah state property posisi dan mengurangi stamina.
  2. jump(): Behavior manusia untuk melompat ke atas lalu mendarat (ekuivalen model Biped di Alice 3).
  3. say(String pesan): Behavior manusia untuk berbicara / menampilkan pesan percakapan (contoh: say("Halo!")).
  4. makan(String makanan, int porsi): Behavior biologis manusia untuk menambah state property energi/kenyang.
  5. tidur(int jam): Behavior untuk mereset dan memulihkan state property stamina menjadi 100%.
SOAL 04 Bobot: 15 Poin Modul Pertemuan 3 (Hal. 2, 6, 7, 8) & Pertemuan 5–6 (Sequence & Abstraction)

"4. Apa yang dimaksud dengan procedure dan mengapa procedure diperlukan dalam pengembangan program?"

Kunci Jawaban Resmi Berdasarkan Diktat Pertemuan 3, 5, 6 UMS

A. Landasan Konsep: Masalah ➔ Algoritma ➔ Instruksi ➔ Program ➔ Output

Berdasarkan Modul Pertemuan 3 Sub-bab 1 & 2:

  • Instruksi adalah perintah yang diberikan agar objek melakukan sesuatu.
  • Objek adalah pihak yang menjalankan instruksi.
  • Program adalah sekumpulan instruksi yang mengendalikan apa yang dilakukan oleh objek.
  • Sequence (Urutan) adalah urutan instruksi yang dijalankan; menentukan hasil atau perilaku program. Komputer menjalankan instruksi secara berurutan sesuai urutan yang diberikan.

B. Pengertian Procedure

Procedure adalah subprogram atau method berisi kumpulan instruksi terstruktur yang mengendalikan aksi/perilaku objek tanpa mengembalikan nilai data (return type void).

C. Studi Kasus Urutan Instruksi Modul Dosen: Robot Mencapai Bendera

Modul Pertemuan 3 Hal. 6–8 mendemonstrasikan bahwa objek yang sama dengan instruksi yang sama, jika urutannya berbeda, menghasilkan perilaku yang berbeda:

Rangkaian Instruksi Urutan yang Diberikan Hasil / Perilaku Program
Urutan Benar (A) move() ➔ move() ➔ turnRight() ➔ move() ➔ move() Robot BERHASIL mencapai bendera.
Urutan Salah (B) turnRight() ➔ move() ➔ move() ➔ turnRight() ➔ move() Robot GAGAL / tidak mencapai bendera.

D. Mengapa Procedure Diperlukan dalam Pengembangan Program?

  1. Procedural Abstraction (Abstraksi Prosedural):
    Daripada menulis 5 baris instruksi dasar move() dan turnRight() berulang kali, kita mengelompokkannya menjadi satu procedure bernama capaiBendera() atau jump(). Kompleksitas detail disembunyikan di balik nama aksi yang bermakna.
  2. Menghindari Duplikasi Kode (Code Reusability / DRY):
    Procedure cukup ditulis satu kali dan dapat dipanggil berulang kali oleh berbagai objek kapan pun dibutuhkan.
  3. Modularitas & Kemudahan Perawatan (Maintainability):
    Jika logika gerakan perlu diubah, programmer cukup menyunting isi procedure tersebut tanpa perlu mengubah puluhan pemanggilan di modul utama.
  4. Mendukung Parameter:
    Procedure dapat menerima argumen (misal capaiBendera(kecepatan) atau jump(arah)) untuk menghasilkan variasi aksi dinamis.

SOAL 06 Bobot: 20 Poin Modul Hal. 18–21 (P4), P6 (Biped), & Slide Netlify (P7)

"6. Apa yang dimaksud dengan Inheritance dalam OOP dan kenapa konsep ini sangat bermanfaat? Berikan contohnya dari modul!"

Kunci Jawaban Resmi Berdasarkan Modul Kuliah

A. Pengertian Inheritance (Pewarisan)

Berdasarkan Modul Pertemuan 4 Sub-bab 21 & Slide Kuliah Netlify: Inheritance adalah mekanisme ketika Child Class (Subclass) mewarisi property dan method dari Parent Class (Superclass), kemudian dapat menambahkan behavior khususnya sendiri.

B. Contoh Struktur Inheritance pada Modul:

  • 1. Hierarki Animal (Modul Hal. 19–21):
    Parent Class: Animal memiliki property name, position dan method move().
    • Child Class Bird mewarisi name, position, move() + specific method fly().
    • Child Class Rabbit mewarisi name, position, move() + specific method jump().
    • Child Class Fish mewarisi name, position, move() + specific method swim().
  • 2. Hierarki Alice 3 (Pertemuan 6):
    Class Biped adalah Parent Class, sedangkan Bunny dan MarchHare adalah Child Class. Procedure jump() ditempatkan pada class Biped sehingga dapat diwarisi dan digunakan oleh keduanya.
  • 3. Final Challenge Penguin (Modul Hal. 24):
    Class Penguin mewarisi move() dan turn() dari Parent Class Animal/Biped, serta menambahkan specific method waddle() (jalan bergoyang).
  • 4. Sintaks Java OOP (Slide Netlify):
    extends & super (Netlify Slide 3, 6, 11) 
    // Keyword 'extends' menyatakan hubungan inheritance
class Vehicle {
    void move() { System.out.println("Moving"); }
}

class Car extends Vehicle {
    @Override
    void move() { System.out.println("Driving"); }

    void start() {
        super.move(); // Keyword 'super' memanggil method parent
    }
}

new Car().start(); // Output: Moving

C. Mengapa Inheritance Sangat Bermanfaat? (3 Keuntungan Utama pada Modul)

  1. Tidak perlu menulis ulang property dan method yang sama (menghindari duplikasi / DRY).
  2. Kode lebih rapi dan mudah dipelihara (perubahan pada superclass otomatis diwarisi seluruh subclass).
  3. Setiap Child Class tetap bisa memiliki behavior khusus (seperti burung bisa fly, kelinci bisa jump, dan penguin bisa waddle).

PERTEMUAN 3 (DIKTAT RESMI UMS)

Dari Instruksi ke Perilaku Program — Blueprint, Sequence & Objek

1. Gambaran Umum: Alur Pemrograman

Materi menghubungkan alur fundamental pemrograman komputer:
Masalah ➔ Algoritma ➔ Instruksi ➔ Program ➔ Output

  • Instruksi: Perintah yang diberikan agar objek melakukan sesuatu.
  • Objek: Pihak di dalam program yang menjalankan instruksi.
  • Program: Sekumpulan instruksi yang mengendalikan apa yang dilakukan oleh objek ("Program = sekumpulan instruksi yang mengendalikan apa yang dilakukan oleh objek").
  • Output / Perilaku: Hasil yang muncul setelah instruksi dijalankan.

2. Program Membentuk Perilaku (Behavior)

Contoh instruksi yang diberikan kepada Robot:

move forward
turn right
say "Hello!"

Hasil perilaku (behavior) yang ditampilkan robot:

  1. Move Forward: Robot bergerak maju.
  2. Turn Right: Robot berbelok ke kanan.
  3. Say "Hello!": Robot mengucapkan kata "Hello!".

Definisi: Perilaku / Behavior adalah hasil aksi yang dilakukan objek setelah instruksi dijalankan.

3. Siapa yang Melakukan Instruksi?

"Ketika kita memberikan instruksi, harus ada objek yang melakukan instruksi tersebut."

Object adalah sesuatu di dalam program yang dapat kita berikan instruksi. Instruksi tidak dapat berdiri sendiri; harus ada objek yang menjalankannya.

4. Tabel Contoh Objek dan Behavior-nya

Objek Behavior / Method Kesesuaian Logika
Robot move(), turn(), stop() Cocok untuk berpindah posisi dan bernavigasi.
Character walk(), jump(), say() Cocok untuk manusia / karakter avatar.
Car move(), turn(), stop() Cocok untuk kendaraan roda empat.
Door open(), close(), lock() Cocok untuk pintu membuka/menutup.
Ball move(), roll(), stop() Cocok untuk benda bulat menggelinding.
Animal walk(), jump(), makeSound() Cocok untuk satwa bersuara/melompat.

Pertanyaan Penting Dosen: "Apa yang terjadi jika kita memberikan instruksi `open()` kepada robot atau `move()` kepada pintu?"
• open() adalah behavior yang cocok untuk Door, bukan untuk Robot.
• move()` adalah behavior yang cocok untuk Robot, Car, atau Ball, tetapi tidak cocok untuk Door.
• Kesimpulan: Tidak semua objek dapat melakukan behavior yang sama. Method harus sesuai dengan jenis objeknya.

5 & 6. Sequence: Urutan Instruksi Menentukan Hasil

"Instruksi yang sama, namun urutannya berbeda dapat menghasilkan perilaku yang berbeda. Komputer menjalankan instruksi secara berurutan sesuai dengan urutan yang diberikan."
  • Urutan Instruksi A: move forward ➔ turn right ➔ move forward ➔ stop (Robot mencapai bendera)
  • Urutan Instruksi B: turn right ➔ move forward ➔ move forward ➔ stop (Robot berbelok duluan ➔ tidak mencapai bendera)

7. Studi Kasus: Membuat Robot Mencapai Tujuan Bendera

Robot sudah bisa move() dan turnRight(). Untuk mencapai bendera pada grid:

  • Urutan Benar: move() ➔ move() ➔ turnRight() ➔ move() ➔ move() ➔ Berhasil!
  • Urutan Salah: turnRight() ➔ move() ➔ move() ➔ turnRight() ➔ move() ➔ Gagal!

8. Object Memiliki Property dan Method

  • Property: Data atau keadaan yang dimiliki oleh sebuah object (misal: warna → "biru", posisi, arah, kecepatan). Property dapat berubah selama program berjalan (contoh: posisi robot setelah bergerak).
  • Method: Aksi atau perilaku yang dapat dilakukan oleh sebuah object (contoh: move(), turnRight(), stop(), say("...")).

9. Kasus Tiga Robot: Robot A, Robot B, dan Robot C

Ketiga robot memiliki method yang sama dan struktur property yang sama, namun memiliki nilai property yang berbeda:

Objek Warna Posisi Arah Kecepatan Method yang Dimiliki
Robot A biru (2, 1) kanan 2 move(), turnRight(), stop()
Robot B merah (4, 2) kiri 3 move(), turnRight(), stop()
Robot C hijau (1, 5) atas 1 move(), turnRight(), stop()

10. Kita Membutuhkan Blueprint (Class: Robot)

Daripada mendefinisikan property dan method berulang kali untuk setiap robot, kita mendefinisikan strukturnya satu kali saja dalam sebuah Class.
Class: Robot mendefinisikan:

  • Property (data): warna, posisi, arah, kecepatan
  • Method (perilaku): move(), turnRight(), stop(), say("...")

11. Class vs Object: Analogi Blueprint Rumah

Dari satu blueprint Class: Rumah (property: warna, jumlah lantai, penghuni, lokasi; method: bangun(), ubahWarna(), tambahLantai()), dapat dibangun:

  • Rumah A: putih, 2 lantai, Keluarga A, lokasi Solo.
  • Rumah B: cokelat, 2 lantai, Keluarga B, lokasi Yogyakarta.
  • Rumah C: abu-abu, 3 lantai, Keluarga C, lokasi Bandung.

Pertanyaan Refleksi Dosen: Jika blueprint rumah diubah, apakah rumah yang dibuat berikutnya ikut berubah?
Ya. Blueprint/class mendefinisikan struktur. Jika blueprint diubah, seluruh objek baru yang dibuat darinya akan mengikuti perubahan struktur tersebut.

2. SINTAKS JAVA OOP NETLIFY DOSEN
class Biped extends SJointedModel {
  void jump() { ... }
}
class Bunny extends Biped {
  @Override
  void jump() {
    super.jump(); // panggil aksi parent
    System.out.println("Telinga goyang");
  }
}

Menggunakan extends untuk mewarisi dan super.jump() untuk memanggil implementasi method parent saat terjadi method overriding.

• Sequence: Susunan instruksi membentuk behavior.

• Procedure: Aksi murni / void (contoh: bunny.jump()).

💡 Tanya Jawab Cepat Seputar Ujian (FAQ)

Pertanyaan yang paling sering membingungkan mahasiswa saat mengerjakan naskah soal UTS Pemrograman Visual.

Apakah di Alice 3 Function bisa langsung menggerakkan objek?

Tidak bisa. Function hanya bertugas membaca atau menghitung data (mengajukan pertanyaan/query) dan mengembalikan nilai (return value). Untuk menggerakkan objek secara fisik di scene, Anda harus menggunakan Procedure (seperti move, turn, atau roll).

Bagaimana cara mudah membedakan kapan memakai While vs Count loop?

Gunakan Count Loop jika jumlah putaran sudah pasti diketahui sejak awal (deterministik, misal: melompat 3 kali). Gunakan While Loop jika durasi perulangan bergantung pada kondisi dinamis yang belum tentu kapan selesainya (misal: berjalan terus selama jarak ke rintangan > 1 meter).

Pada diagram relasi kelas UML, ke mana arah panah inheritance?

Arah panah selalu ditarik dari Subclass (kelas anak) menuju Superclass (kelas induk) dengan kepala panah berbentuk segitiga kosong (hollow triangle). Ini melambangkan relasi bahwa Subclass merupakan turunan spesifik dari Superclass (relasi is-a).
